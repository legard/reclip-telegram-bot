# Русская аудиодорожка YouTube в ReClip Bot

## Контекст

ReClip Bot скачивает видео через `yt-dlp`, но для MP4 всегда выбирает обычную
дорожку `bestaudio`. YouTube может публиковать отдельные русские дорожки,
включая автоматический дубляж. Пользователь должен иметь возможность явно
скачать видео с такой дорожкой, не меняя поведение существующих MP4 и MP3.

Проверочная ссылка:
`https://www.youtube.com/watch?v=M6mYodf0dJM`. При русской локали YouTube
помечает русскую дорожку кодом `ru` и `isAutoDubbed=true`; `yt-dlp` может
представлять её как отдельный audio-only формат или как совмещённый HLS-поток
video+audio. Идентификаторы форматов между запросами не считаются стабильными.

## Цель и границы

Цель — добавить в Telegram-бот кнопку `MP4 • RU`, которая появляется только
для YouTube-видео с отдельной русской дорожкой, предлагает доступные для неё
разрешения и отправляет MP4 с русским звуком.

В рамках изменения:

- принимается любая отдельная русская дорожка YouTube: автодубляж или
  загруженная автором озвучка;
- исходная русская дорожка не создаёт отдельную кнопку;
- обычные MP4 и MP3 сохраняют текущее поведение;
- веб-интерфейс ReClip не получает новый переключатель;
- поддержка русских дорожек на сайтах кроме YouTube не обещается;
- при недоступности русской дорожки оригинальный звук не подставляется.

## Архитектура и поток данных

### Обнаружение

`POST /api/info` сохраняет текущий обычный probe `yt-dlp`. Для URL, которые
извлечены как YouTube, ReClip выполняет дополнительный локализованный probe с
`youtube:lang=ru`.

Из локализованного результата выбираются форматы с языком `ru` или региональным
вариантом `ru-*`, содержащие аудио. Отдельная опция нужна только тогда, когда
исходная дорожка ролика не русская. Исходный язык определяется по обычному
probe: используется язык аудиоформата, который `yt-dlp` помечает как original
или даёт ему наивысший `language_preference`. Доступные разрешения строятся
так:

- если есть русская audio-only дорожка, доступны разрешения обычных
  видеоформатов;
- если русский звук доступен только в совмещённых video+audio потоках,
  доступны только их разрешения;
- одинаковые разрешения дедуплицируются и сортируются по убыванию.

Сбой дополнительного probe не ломает обычный `/api/info`: причина записывается
в журнал, а русская опция считается недоступной.

### Telegram-поток

Ответ `/api/info` расширяется полем:

```json
{
  "russian_audio": {
    "available": true,
    "formats": [
      {"height": 1080, "label": "1080p"},
      {"height": 720, "label": "720p"}
    ]
  }
}
```

Поле всегда имеет одинаковую форму; при отсутствии дорожки возвращаются
`available: false` и пустой список `formats`.

Бот добавляет `MP4 • RU` рядом с текущими `MP4` и `MP3`, только когда
`russian_audio.available=true`. После нажатия показываются русскоязычные
варианты качества и `Best quality`. Callback хранит разрешение, а не
идентификатор формата YouTube. Выбор `Best quality` передаётся без ограничения
по высоте.

### Запуск загрузки

`POST /api/download` получает два необязательных поля:

```json
{
  "audio_language": "ru",
  "height": 1080
}
```

Без `audio_language` запрос полностью совместим с существующим контрактом.
Для первой версии единственное допустимое значение `audio_language` — `ru`.
`height` должен быть положительным целым числом; его фактическая доступность
повторно проверяется по свежим метаданным во время загрузки. Отсутствие
`height` означает лучшее доступное русскоязычное качество.

Русскоязычная загрузка повторно извлекает YouTube с `youtube:lang=ru` и строит
селектор в следующем порядке:

1. видео выбранной высоты плюс лучшая audio-only дорожка `ru`;
2. совмещённый video+audio формат выбранной высоты с языком `ru`;
3. те же варианты без предпочтения H.264, чтобы не считать доступную дорожку
   отсутствующей только из-за кодека.

Первые два варианта предпочитают H.264 для совместимости с Telegram. В каждом
селекторе присутствует фильтр языка; общей ветки `best` без `language=ru` нет.

Для `Best quality` применяется тот же порядок без фильтра высоты. Выходной
контейнер остаётся MP4. Существующая постобработка продолжает перекодировать
AV1/VP9/VP8 в H.264 и добавлять faststart.

## Валидация и ошибки

- Неизвестный `audio_language`, неположительный или нецелый `height`, а также
  русская дорожка для не-YouTube URL дают HTTP 400 до запуска фонового задания.
- На этапе скачивания язык снова фильтруется по метаданным `yt-dlp`; клиентский
  callback не может передать произвольный format ID.
- Если подходящего русского формата больше нет, задание завершается ошибкой
  `Russian audio track is no longer available. Please retry.`.
- Ошибка никогда не запускает обычный селектор и не отправляет видео с
  оригинальным звуком.
- Ограничение параллелизма, общий дедлайн, очистка частичных файлов,
  постобработка и отправка через локальный Telegram Bot API остаются общими для
  обычных и русскоязычных заданий.

## Runtime и зависимости

Образ `reclip` должен содержать поддерживаемый `yt-dlp` JavaScript runtime и
совместимые EJS-скрипты. Python-зависимость устанавливается как
`yt-dlp[default]`, чтобы EJS поставлялся вместе с образом, без скачивания кода
при рабочем запросе. Runtime должен поддерживаться на `linux/amd64` и
`linux/arm64`; предпочтителен Deno, который `yt-dlp` включает по умолчанию.

CI проверяет наличие runtime и EJS в собранном образе наряду с существующими
multi-arch контрактами.

## Тестирование и приёмка

Автотесты должны покрыть:

- обнаружение отдельной русской дорожки и дедупликацию разрешений;
- отсутствие отдельной кнопки для исходного русского ролика, не-YouTube URL и
  ролика без русской дорожки;
- условное появление `MP4 • RU`, выбор качества и payload загрузки;
- селекторы для audio-only плюс video и для совмещённого HLS;
- валидацию новых полей и понятную ошибку исчезнувшей дорожки;
- отсутствие fallback на оригинальный звук;
- неизменность существующих MP4/MP3 сценариев;
- наличие JS runtime и EJS в образе ReClip.

Ручной smoke-тест выполняется на
`https://www.youtube.com/watch?v=M6mYodf0dJM`: бот показывает `MP4 • RU`,
скачивает выбранное качество, отправляет воспроизводимый MP4 с русской речью и
удаляет временный файл после успешной отправки.

## Выпуск

После прохождения тестов публикуется следующая версия multi-arch образов
ReClip. Digest новых образов закрепляются в Ansible-репозитории, после чего
стек разворачивается на текущем сервере ReClip. Приёмка завершается только
после успешного Telegram smoke-теста с проверочной ссылкой.
